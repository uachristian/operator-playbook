# Contributing

- Keep it generic. Use placeholders such as `<business>`, `<owner>`, `<CRM>`. No real company names, people, hostnames, addresses, IDs, or paths from a real machine.
- Keep it harness-agnostic. Put harness-specific detail in `adapters/` or a clearly labeled section.
- One rule per bullet, imperative voice, no filler.
- Every doc must stand alone. Relative links must resolve.
- Never weaken a safety gate to make a workflow shorter. Propose a safer shortcut instead.
- Run a secret scanner over your change before opening a pull request.
- By contributing you agree your work is licensed under the MIT License in this repo.
